# Session recovery audit - beta.12

## Findings and corrections

The reported symptom was a repeated questionnaire followed by a generic save error. Inspection of the affected live session found all its answers saved and its finalized flag set. No private answers or training material are included here. The exact host event that remounted the card was not captured; the source and browser regression reproduce the failure mechanism.

| Priority | Finding in beta.11 | Correction |
| --- | --- | --- |
| P1 | UI startup restored only optional host widget state. Without that cache it reset to question 1, even when the server session was finalized. | Read and validate authoritative server state before showing the form; resume or show completion. |
| P1 | Re-presenting a session reset finalized to false. Different question definitions could reuse an ID. | Preserve the state for an identical definition; reject changed definitions without overwriting answers. |
| P2 | The save transport treated all errors as a failed write, including lost acknowledgments after successful writes. | Read back and compare the submitted answer; reconcile finalization similarly. Preserve the draft if unconfirmed. |
| P2 | Repeated rapid navigation could start duplicate operations; Skip bypassed boundary checkpoints. | Serialize actions with a synchronous guard and checkpoint skipped boundary questions. |
| P2 | Finish could close a session despite invalid current input; completion hid finalization errors. | Require valid current input, keep explicit Skip, and display a failed finalization. Partial completion remains supported without inventing answers. |
| P2 | Agent guidance lacked an explicit recovery step for this symptom. | Read the active session before repeating questions or declaring data loss. |

## Security and scope

Reviewed first-party server, storage, UI, shared validation, MCP registration and tests. No new network destination, credential access, telemetry or background process was added. Read-only metadata on sequence presentation was corrected because presentation writes the temporary queue. Existing input validation and hashed bounded storage remain.

The temporary queue is not a durable journal: 20 sessions / 24 hours, shared within the OS user's temporary store. Session IDs are routing identifiers, not authorization tokens. OS-user access and cross-process simultaneous updates remain design limitations; atomic replacement alone is not transactional concurrency control. The agent must persist confirmed answers in the user's project. A registry dependency audit was also run. Compatible transitive updates to fast-uri, hono, qs and nanoid removed the reported advisories; the final npm audit reports zero known vulnerabilities across 174 packages. This is a dated registry result, not proof of zero risk or a penetration/accessibility audit.

## Verification

Regression coverage includes restoring multi-select and Other, finalized and partially completed sessions, malformed/stale snapshots, lost save acknowledgments, server restart, unchanged sequence replay, conflicting definitions, and a browser card connected to the real MCP server through a simulated host bridge. Tests use isolated temporary stores rather than live user sessions.

The browser test exercises built assets, not preview fixtures. It deliberately provides no host widget cache and drops successful save/finalize replies. A native Codex host reload with the new plugin remains a separate validation step.
